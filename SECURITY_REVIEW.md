# Backup scope and preserved security

The published application code is unchanged by the source backup. Included
runtime files are independently matched to the current HTTPS site. The financial
interpreter remains separate from the opaque-origin strategy Web Worker; iframe
sandbox permissions, network restrictions, headers, deadlines and resource
bounds are preserved. Runtime assets are checksum pinned and workers must prove
the Context /2 contract before strategy execution.

Browser Python remains trusted-code-only. A browser cannot supply a hard memory
limit or OS-container-equivalent isolation for hostile code. No server secrets,
production wallet database or other account's files are supplied to the worker.

Before pushing, the proposed source tree is scanned for private-key blocks,
known credential formats, literal credentials in URLs/configuration and configured
secret values without printing those values. Vendored archives and synthetic
fixture archives are also inspected within bounded expansion limits. Filename
and inventory checks exclude environment files with values, databases, profiles,
credential files, original market caches and unrelated projects. The scan report
contains paths/categories and counts, never secret values.

Current-source SHA-256 manifests and a fresh-clone comparison protect against
missing or changed files. A scan is not a mathematical guarantee that arbitrary
text cannot contain a secret; credible unresolved findings block the push.
Do not bypass GitHub push protection if it raises a finding.

The backup includes only the public Backtester's source, approved SMC example,
test fixtures/oracles from disposable accounts and documentation. It contains
no private Trading Terminal/ABG implementations, sealed labels, owner browser
profiles, production account state or live wallet exports.
